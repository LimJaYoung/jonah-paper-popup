# 01·04 · 실제 음성, 05 · 영어 싱크 조정

제작 순서·통과 조건은 `PRODUCTION_PLAYBOOK.md`를 따른다. 현재 한국어 시리즈는 Typecast 실제 파일 가져오기를 사용한다. 영어 서비스·배역은 별도 선정하며 연결·생성 지원 여부를 확인한다. 영어 음성 생성·실측·웹 연결·자막/장면 타이밍 검수의 담당자는 맥북의 이 대화에서 Codex다(v3.2.2, 2026-10-14 사용자 정정). PC 음성 요청·회신을 영어 제작의 선행 조건으로 두지 않는다. PC에는 완성 음성·타임라인을 출력 입력으로 전달한다. 예전 OpenAI TTS 설정으로 임의 대체하지 않는다.

한국어 실제 음성을 포함한 전체 제작·검수가 끝나고 PLAYBOOK 03 완성을 확정한 뒤, 04에서 영어 대본·음성을 자동 제작한다. 자동 경로에도 아래 실제 샘플·배역·MP3/SRT·실측·청취 기준을 동일하게 적용한다. 미구현·차단·서비스 실패는 그대로 기록한다. 기존 유료 생성 금지나 승인 범위는 절차 문서만으로 바뀌지 않는다.

## 1. 배역부터 확인

한국어 시리즈 공통은 내레이터 `narrator` = 나윤, 하나님 `god` = 권일이다. 새 인물은 해당 인물의 짧은 실제 대사로 샘플을 만들어 선택한다. 요나의 확정 배역은 작품 `STORY_RULES.md`에 있다. 같은 역할의 유효한 승인을 반복해서 묻지 않는다.

차분하고 자연스러운 한국어를 사용한다. 외국 억양처럼 들리는 말투, 지나치게 낭랑한 음색, 역할에 맞지 않는 목소리를 피한다. 실제 들은 것만 청취했다고 기록한다. `voiceCasting`·manifest의 배역 정보와 실제 파일을 대조한다. 오래된 `voices`의 API 후보 이름이나 메모를 더 최신 근거로 취급하지 않는다.

유료 생성은 실제 플랜·가격과 이미 승인된 범위를 확인한다. 결제 이력이 무제한 추가 지출 허가는 아니다. 기존 승인 범위의 실행을 매번 다시 묻지 않는다. 접근할 수 없는 Typecast에서 생성·다운로드를 했다고 주장하지 않는다. 파일을 요청할 때는 대상 작품, 필요한 배역, 확정 대본 버전, MP3/SRT를 한 번에 명확히 안내한다.

영어 나레이터와 등장인물 목소리는 실제 영어 샘플로 정하고 언어별로 작품 안에서 일관되게 유지한다. 한국어 확정 성우를 영어 배역으로 자동 확정하지 않는다. 서비스 미연결·생성 실패·파일 미확보는 해당 언어/발화·원인·필요 조치를 미완료로 기록한다. 텍스트 준비를 실제 음성 완성으로 보고하지 않는다.

## 2. 가져오기 순서

1. 해당 언어의 확정 대본 원본(기존 한국어는 `story.json`)에서 공통 장면 ID와 발화 ID·화자·문장 순서를 추출하고 녹음용 문서와 대조한다.
2. 확정 배역으로 만든 합본 MP3와 정확히 대응하는 SRT를 확보한다. 이름보다 내용·문장·시간을 확인한다.
3. 언어별 음성을 장면·발화 단위로 분리하고 ko/en·장면 ID·발화 ID·실측 길이·원본 위치로 관리한다. 언어별 manifest·믹스·SRT·타임라인을 구분하고 덮어쓰지 않는다. 대상 ID와 기존 음성을 확인하고 필요하면 버전을 보존한다. 가져오기는 기존 음성 목록과 파생 파일을 갱신한다.
4. 제작실의 MP3 가져오기에서 선택 언어와 문장 ID를 확인한다. 한 문장 MP3 또는 전체 MP3+정확히 대응하는 SRT를 가져온다. 영어는 실제 샘플 확인을 표시한 Typecast 배역이 필요하다. CLI는 `node scripts/import-typecast.mjs <story-id> '<MP3 절대경로>' '<SRT 절대경로>' --lang en`이며 한국어는 `--lang ko`다. 단일 문장은 `--cue <발화ID>`를 사용한다. 언어 데이터 경로는 STORY_GUIDE를 따른다.
5. SRT 수와 `utterances` 수·문장 문자열이 정확히 맞아야 한다. 합쳐진 자막은 경계를 바로잡는다. 음수·시간 역전·중첩·음원 길이 초과를 강제 통과시키지 않는다.
6. 각 언어의 `audio/typecast-original/<원본해시>/full.mp3`, `full.srt`와 문장별 MP3를 보존한다. 이전 원본을 덮어쓰지 않는다. 192kbps/44.1kHz/mono로 분리하고 ffprobe 실측 길이를 기록한다.
7. `audio/manifest.json`은 cue ID를 키로 provider·voiceName·speaker·text·duration·sourceHash·sourceStart/End·file·hash를 가진다. 파일이 실제 존재하며 현재 문장·배역과 맞는지 확인한다.
8. 한국어는 `mix.wav`, `output/timeline.json`, `subtitles/ko.srt`, 영어는 해당 `languages/en/` 아래 음성·타임라인·영어 SRT 경로를 실제 구현과 대조해 같은 언어·버전으로 재생성한다. 영어 작업에서 한국어 경로를 덮어쓰지 않는다. 예전 타임라인과 새 합본을 섞지 않는다.
9. 모든 문장의 발음·어미·감정·무음·잘린 음절·음량을 듣고 기록한다. 메타데이터 검사는 청취가 아니다.

sourceProject는 가져온 음성의 실제 출처를 선택적으로 기록한다. 다른 작품의 주소를 자동으로 복사하지 않는다. 문장별 가져오기는 화자·문장 연결과 MP3 재생 길이를 확인하며 음성 인식으로 실제 발화 내용을 검증하지는 않는다. 자동 음성 생성 서비스는 연결하지 않았고 유료 호출도 하지 않는다.

제작실 재생은 현재 언어의 유효한 문장별 MP3를 사용한다. 이전 mix.wav를 문장 수정 후 재사용하지 않는다. 음원 로딩/재생이 끝나기 전에는 타임라인을 먼저 진행시키지 않는다. 가져오기 완료 뒤 자막·타임라인을 갱신하고 최종 출력에서 별도 믹스를 생성한다.

## 3. 실제 말에 연기를 맞추기

각 언어의 실측 음성 길이와 문장 읽기 시간을 함께 고려한다. 두 언어의 영상 길이는 달라도 되며 길이를 맞추려고 배속하거나 문장을 자르지 않는다. 현행 `compileTimeline`은 `max(읽기 시간, 실제 음성 길이) + endPause`를 사용하며, `endPause` 미지정 기본값은 0.25초다. 기존 작품의 0.1초 설정은 작품별 값이다. 새 작품에 요나의 측정값·무음 위치·총 길이를 복사하지 않는다.

사건을 나타내는 말의 시작·끝·핵심 구절에 실제 녹음 시점을 표시한다. 그 시점에 손 내밀기·왕 등장·문 닫힘 등이 맞는지 실제 재생한다. 장면 전환에는 음성뿐 아니라 필수 동작 종료도 반영한다. 구체적 완료 조건은 `ANIMATION_GUIDE.md`를 따른다.

말이 끝난 뒤 불필요하게 남는 대기는 줄이고, 읽기 전에 사라지는 자막은 시간을 늘린다. 문장 자체를 줄이거나 전체 음성을 배속해 해결하지 않는다. 문장이 바뀌면 해당 녹음을 다시 준비하고 자막·연기·타임라인을 함께 갱신한다.

## 4. 효과음과 믹싱

책·종이·파도 등 실제 사건에 필요한 효과음을 사용한다. 배경음과 효과음은 음성에서 분리해 공통 자산으로 관리하고 언어별 실제 타이밍에 맞춰 각각 합성한다. 각 음원은 개별 관리하고 사용 가능한 음원인지 확인한다. 음성이 명확하게 들려야 한다.

현재 믹서는 48kHz stereo, loudnorm -16 LUFS 목표/true peak -1.5dB, 음성 중 배경 25% 처리를 사용한다. 설정값이 실제 듣기 품질을 보장하지 않는다. 최종 파일에서 겹침·갑작스러운 음량 변화·잘린 끝을 듣는다. 합성 화음·효과음을 전문 녹음 음악처럼 설명하지 않는다.

설명에 AI 음성 사용을 표기한다. 게시 시점의 이용 조건을 확인하며 계정 인증·결제 정보·토큰을 문서에 남기지 않는다.
