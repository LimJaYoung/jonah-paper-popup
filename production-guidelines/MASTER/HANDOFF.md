## 종료 순서

1. 실제 완료 범위와 미확인을 구분한다. 결과물 경로·버전·검수 범위를 확인한다.
2. 작품 `PRODUCTION_NOTES.md`의 현재 항목을 갱신한다. `PRODUCTION_RECORD_TEMPLATE.md` 양식을 따른다. 매번 새 공지를 붙이지 않는다.
3. 변경된 확정 사항은 `STORY_RULES.md` 해당 항목에 반영한다. 이전 값·변경 이유는 이력에 보존한다. 관련 없는 승인과 원본은 유지한다.
4. 지침을 고쳤으면 `node scripts/sync-production-guide.mjs`로 표시본을 갱신한다. 웹 저장소는 `public/guide.html`, PC 프로젝트는 `DASHBOARD/guide.html`이다. 해당 환경의 기존 생성기를 사용하며 표시본만 직접 수정하지 않는다.
5. 제작 중 열어둔 미리보기는 사용자가 확인할 수 있게 유지한다. 사용자 탭·재생 위치를 불필요하게 바꾸지 않는다. 제공 도구가 지원하면 결과 탭으로 남긴다. 다른 환경의 로컬 서버가 사용자 브라우저에서 보인다고 단정하지 않는다.
6. GitHub 원격 SHA·push 상태와 웹 소스 SHA·배포 버전/ID·실제 성공 상태/URL을 구분해 확인한다. 영상 언어별 자동 검수·사용자 최종 검수·최종 승인·공개 클릭·실제 public 상태/URL도 기록한다. 실패·미실행·미확인을 완료로 기록하지 않는다.
7. 대상·바뀐 점·검수·미완료·다음 한 단계·실제 결과 링크를 짧게 보고한다. 끝까지 보거나 듣지 않았으면 그 사실을 적는다.

## 완성 전 음성 제작과 인계 · v3.2.2

### 영어 맥북 직접 제작 기록

영어 음성 생성·실측·웹 제작소 연결·자막/장면 타이밍 검수는 맥북의 이 대화에서 Codex가 직접 담당한다. 영어 대본·배역·기존 비용 승인 범위를 확인하고, 실제 파일/해시/길이·발화 대응·청취 여부·웹 연결 revision·싱크 검수 결과를 기록한다. 실패·재시도·기존 파일 재사용과 최신본 충돌 검사는 아래 계약과 같은 기준을 적용한다. PC ACK나 audio.ready 회신을 영어 제작의 필수 조건으로 요구하지 않는다. 검수가 끝난 영어 음성·SRT·타임라인을 PC의 MP4·출력 검수·비공개 업로드 입력으로 전달한다. 담당 변경은 유료 생성 승인이나 음성 제작 완료의 증거가 아니다.

### PC에 별도로 맡긴 한국어 음성 요청·회신 계약

PC에 별도로 맡긴 한국어 음성은 PLAYBOOK 01-C에서 요청한다. 영어 04는 위 맥북 직접 제작 절차를 따른다. 음성을 받아야 전체 싱크·청취 검수를 할 수 있으므로 이 요청에 `content.completed`나 완성본 배포 성공을 요구하지 않는다. 이 절은 전달 계약의 보완안이다. 기존 PC 구현과 매핑·담당 합의·실제 연동 검증 전까지 새 API나 자동 수신이 구현됐다고 표시하지 않는다.

### 이미 완료한 음성의 보존과 철회

사용자가 기존 음성 제작 완료를 확정한 경우 해당 완료 파일·manifest·실측 타임라인을 먼저 확보·대조한다. 전달 자료 누락이나 웹 연결 누락을 신규 생성 허가로 해석하지 않는다. 기존 파일을 확보하며, 문장·화자·언어·해시가 다른 파일은 메타데이터만 바꿔 연결하지 않는다. 음성 제작 완료, 최신 대본과의 파일 대응 확인, 전체 작품 시청·청취·전환 검수는 각각 기록한다. 유효한 기존 승인과 검수는 보존한다.

철회된 요청은 원문과 이전 상태 이력을 보존하고 철회 사유·사용자 근거·시각을 추가한다. 취소 전용 상태가 없는 기존 요청 목록은 처리 보고에 철회를 명시하고 실행 대상에서 종료하되, 작품 제작 완료로 집계하지 않는다. PC의 실행 중단·수신 확인은 PC 회신이 있을 때만 기록한다. 이번 2026-10-14 요나 한국어는 맥 완료 음성과 타임라인을 그대로 사용하며 PC 신규 음성 생성·임의 타이밍 변경 대상에서 제외한다.

### 요청·수신·회신·완성의 구분

| 기록 | 작성자 | 의미와 다음 단계 |
|---|---|---|
| `audio.requested` | MAC | 확정 대본의 누락·변경 음성 준비 요청. 원본·배역·기존 비용 승인 범위 확인 후 발행 |
| 요청 ACK `accepted` / `rejected` | PC | 요청 수신·입력 검사 결과. `accepted`는 음성 생성·연결 성공이 아님 |
| `audio.ready` / `audio.failed` | PC | 실제 음성 파일·실측·manifest·검사 근거 회신, 또는 실패한 발화·원인 기록 |
| 회신 대조·연결 기록 | 지정 담당자 | 최신 저장본과 다시 대조하고 공유 재생 연결의 지정 담당자가 적용. 대본·연출을 자동 변경하지 않음 |
| `content.completed` | MAC | 회신 음성을 연결한 해당 언어의 전체 검수·완성본 배포 검수까지 통과한 뒤 발행 |

웹 요청 게시판의 기존 요청 ID·완료 보고는 근거로 연결하되 새 이벤트의 ACK로 자동 변환하지 않는다. 한 요청의 완료를 작품 전체 완료로 전용하지 않는다.

### `audio.requested`에 고정할 입력

| 필드 | 기록 기준 |
|---|---|
| `schemaVersion`, `eventType`, `requestId` | 제안 스키마 1, `audio.requested`, 동일한 입력·승인·생성 설정의 재전송에는 동일 ID |
| `storyId`, `language`, `sourceRevision`, `sourceHash` | 요청 시점 실제 웹 저장본. 전체 저장 데이터 해시와 아래 발화별 해시의 계산 범위를 구분 |
| `inputFiles` | 대본 스냅샷·배역·사용자 타이밍·검수/승인 근거의 상대 경로와 실제 바이트 SHA256 |
| `changedCues` | 장면 ID·발화 ID·정확한 문장·화자·배역/서비스 식별자·언어·생성 설정·이전 음성 해시·변경 사유 |
| `unchangedCues` | 재사용 후보와 기존 문장·화자·배역/설정·오디오 해시. 다른 발화를 불필요하게 재생성하지 않음 |

| `baseKoVersion`, `baseKoHash` | 영어는 검증된 한국어 기준 필수. 한국어는 null |
| `guidelineVersion`, `createdAt` | 적용 지침과 ISO 8601 시각 |

요청 입력은 별도 묶음으로 보존하며 사용자 작업 트리나 운영 DB를 덮어쓰지 않는다. Git 전달이 이미 승인된 경우에는 입력 commit과 후속 요청 commit을 나눈다. 기존 요청 게시판·승인된 파일 전달을 사용하는 경우에는 전달 위치·요청 ID·파일 해시를 기록한다. 완성 전 요청 전달을 이유로 완성본 push·배포가 끝났다고 표시하지 않는다. 미확정 문장·배역·비용 조건이 있으면 요청 초안만 준비하고 그 조건이 필요한 실제 생성은 진행하지 않는다.

### PC 처리와 회신

1. PC는 기존 음성 엔진과 승인 검사를 재사용한다. 요청 ID·입력 해시·발화 지문으로 영속 중복 처리를 막고 같은 요청의 재전송은 원래 작업 상태를 반환한다. 같은 ID에 다른 입력이 오면 충돌로 거절한다. 키·토큰은 회신하지 않는다.
2. 변경·누락 발화만 준비한다. 재사용은 문장·화자·배역·언어·생성 설정·파일 해시 일치가 확인될 때만 허용한다. 사용자 지정 음수 `visualHoldSeconds`, 장면 시간·순서·배치·꾸미기를 임의로 초기화하지 않는다.
3. `audio.ready`에는 requestId, storyId, language, 요청 당시 revision/해시, PC 엔진 commit, 생성·재사용·실패 발화 목록, 각 파일 경로/SHA256/실측 길이, manifest/SRT/타임라인 근거와 시각을 기록한다. 발음·배역·끝 음절 청취 여부와 자동 파일 검사 결과를 분리한다. 파일 존재와 메타데이터 일치만으로 청취 통과를 만들지 않는다.
4. 일부 발화 실패는 `audio.failed`와 성공한 개별 결과로 남긴다. 전체 ready로 표시하지 않으며 성공 파일은 보존한다. 응답 불명·중단 뒤에는 기존 작업/서비스 결과부터 조회하고 중복 과금 생성에 앞서 복구한다.

### 늦게 도착한 회신과 재검수

연결 직전에 최신 저장본을 읽어 요청 당시와 비교한다. revision/전체 해시가 같으면 발화·파일 검사 후 기존 revision 충돌 보호를 통해 연결한다. 다르면 자동 적용을 멈추고 발화별 차이를 계산한다. 요청 후 문장·화자·배역/설정이 바뀐 발화에는 과거 회신을 연결하지 않는다. 타이밍·배치만 바뀌었다면 오디오 재사용 가능성과 별개로 최신 사용자 값을 보존하고, 새 타임라인·자막·전체 길이·전환을 재검수한다. 같은 변경을 두 환경에서 동시에 처리하지 않는다.

최종 대조는 도입을 포함한 전체 발화에 대해 수행한다. 변경 음성의 실제 청취, 해당 장면과 앞뒤 전환, 전체 정상속도 시청·청취가 완료돼야 한국어 02→03 또는 영어 05를 통과한다. PC에 요청한 작업은 PC 회신·연결·검수 전 PC 성공 기록을 대신 만들지 않는다. 영어는 맥북 직접 제작·연결·전체 검수 근거를 사용하며 해당 언어의 완성 조건을 충족하기 전 `content.completed`를 발행하지 않는다.

## 제작 완료 송수신 계약 · v3.2.1

맥북 송신과 PC 수신·제작은 별도 구현이다. 아래는 신규 계약 요구이며 PC가 수용·실제 검증하기 전에는 자동 연동 완료가 아니다. API/엔진 담당 문서는 PC 변경 요청으로만 전달한다.

| 필드 | 의미 |
|---|---|
| schemaVersion, eventType | 1, content.completed |
| jobId | 작품·언어·contentVersion·입력 SHA256으로 결정되는 재시도 시 동일한 식별자 |
| storyId, language | 작품 ID, ko 또는 en |
| contentVersion, guidelineVersion | 고정 콘텐츠 버전, 적용 지침 버전 |
| repository, branch, commitId | 승인 입력을 포함하는 GitHub 저장소·MAC 브랜치·전체 SHA |
| contentPaths, files | 해당 commit의 상대 파일 경로 및 각각의 SHA256 |
| sourceRevision, sourceHash | 웹 저장 revision과 전체 저장 데이터 해시 |
| baseKoVersion, baseKoHash | 영어의 기준 한국어 버전·해시; 한국어는 null |
| review | passed 상태, 검수 문서 경로·해시, 범위·시각·검수자; 미확인 항목이 있으면 발행 금지 |
| approval | 승인 대상 언어·입력 해시·근거 경로·해시; 영어는 사용자 대본 승인 필수 |
| deployment | GitHub 입력과 Sites 소스 SHA 매핑, 배포 ID·URL, 전체 재생 검수 근거 |
| createdAt | ISO 8601 시각; 비밀키·토큰 제외 |

완료 이벤트는 콘텐츠 commit 뒤 별도 송신 commit에 둬 자기 commit SHA를 자기 파일에 넣는 순환을 피한다. 파일 경로는 저장소 내부 상대 경로만 허용하고 심볼릭 링크·상위 경로·비밀/백업/전체 PC 자료를 제외한다. 파일 바이트와 검수·승인 증거는 입력 commit에 포함되어야 한다. 소유권 목록 밖 파일은 송신하지 않는다.

송신 성공은 원격 브랜치에서 이벤트와 입력 SHA를 다시 읽어 일치할 때만 기록한다. 네트워크 오류는 로컬 outbox를 보존하고 같은 jobId로 재시도한다. PC는 승인 브랜치에서 fetch해 격리 디렉터리에 정확한 commit을 확보하고 파일/승인/언어/해시를 확인한다. 운영 브랜치의 자동 merge, dirty 작업 트리 reset, 전체 폴더 덮어쓰기는 금지한다.

PC는 jobId 영속 중복 방지와 한 작품·언어의 실행 잠금을 적용하고 accepted/rejected 상태, 입력 commit·해시·PC 엔진 commit·시각·사유를 ACK에 남긴다. 수신 → MP4 제작 → 영상·음성·자막 검수 → private 업로드 → 결과 기록의 각 단계 결과를 추가 이력으로 보존한다. 업로드 결과 불명 시 기존 세션/영상 ID를 조회하기 전 신규 업로드하지 않는다. 실패는 후속 단계를 차단하며 재시도 상한·복구 근거·재검수 결과를 남긴다. 새 입력은 새 jobId로 처리하고 이전 결과를 최신으로 표시하지 않는다.

기록 스키마: jobId, storyId, language, inputCommit, inputHash, stage, status, attempt, startedAt, endedAt, actor, evidencePaths, errorCode, errorMessage. PC 결과에는 outputPath/MP4 SHA256/SRT SHA256/검수 결과/videoId/channelId/privacyStatus/처리 상태/확인 시각을 추가한다. MAC은 PC가 기록한 증거를 읽고 상태만 집계하며 PC 기록을 성공으로 대신 작성하지 않는다.

수신 자동화가 실제 검증되기 전에는 scheduler 활성화·무인 완료를 보고하지 않는다. GitHub push, Sites 배포, PC ACK, MP4 검수, YouTube private 확인을 각각 별도 상태로 보고한다.

## 긴 대화·컨텍스트 요약·새 세션에서 이어가기

대화 기억만으로 재개하지 않는다. AGENTS → DESIGN_ANIMATION_PROTOCOL의 실제 이미지 → 대상 STORY_RULES → PRODUCTION_NOTES의 현재 재개 기록 → 실제 작업 파일·배포 상태 순으로 대조한다. 최신 사용자 요청을 우선하며 미완료를 완료로 추정하지 않는다.

의미 있는 작업 단위 완료, 사용자 정정, 배포, 보류·중단, 컨텍스트 정리 전에 현재 재개 기록을 갱신한다. 종료 직전까지 기록을 미루지 않는다. 요약 시점을 미리 감지하거나 모든 세션의 실행을 자동 보장하는 기능은 아니다.

기록에는 목표·최신 요청·유지할 결정·실제로 연 이미지 경로와 관찰 특징 3개·변경 파일·완료/미완료·마지막 검수 장면과 시간·남은 결함·소스 및 배포 상태·다음 한 행동을 포함한다. 경로 없는 “위 그림”, 증거 없는 “완료”, 인증 정보는 쓰지 않는다. 사용자 중단 요청 시 저장 후 멈춘다.
