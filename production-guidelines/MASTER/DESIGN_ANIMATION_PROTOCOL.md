# 디자인·애니메이션 공통 제작 기준과 시각 참고

버전 1.2 · 2026-10-18 · 모든 새 작업·수정·재개 세션의 필수 읽기

## 작업 시작: 글과 이미지를 함께 확인

1. PRODUCTION_PLAYBOOK 전체와 이 문서를 읽고, 아래 미리보기 이미지를 이미지 보기 도구 또는 실제 브라우저로 연다. 파일명·alt 문구만 읽는 것은 이미지 확인이 아니다.
2. 대상 작품의 최신 승인 시안과 인물 기준도 실제로 연다. 아래 요나 예시는 품질의 참고이며 다른 작품의 의상·색상·인물을 요나로 바꾸라는 지시가 아니다.
3. 작업 기록에 지침 버전, 실제로 연 이미지 경로, 관찰한 시각적 특징 3개, 유지할 요소, 이번 변경 범위를 남긴다. 이미 받은 승인을 다시 요청하지 않는다.
4. 최신 사용자 정정이 과거 시안보다 우선한다. 이미지 도구가 없거나 파일을 열지 못하면 시각 확인을 미확인으로 기록하고 확보 가능한 자료부터 확인한다. 보지 않은 이미지를 숙지했다고 보고하지 않는다.

이 절차는 새 세션·재개 세션·인계 세션에 적용한다. 기존 실행 중인 모든 AI에 자동으로 전달되거나 강제 실행되는 기능은 아니다. 각 세션은 최신 소스의 AGENTS.md부터 다시 확인한다.

## 시각 참고 1 · 사용자 승인 완성 시안

![승인 시안: 물고기 뱃속에서 두 손을 모아 무릎 꿇고 기도하는 요나](/guide-references/jonah-belly-approved.jpg)

2026-10-17 대화에서 사용자가 “너무좋다”로 승인한 물고기 뱃속 장면의 디자인 시안이다. 정지 이미지이며 동작·페이지 접힘 검수의 증거는 아니다. 저장소 이미지 경로: public/guide-references/jonah-belly-approved.jpg. 미리보기는 원본에서 변환한 JPEG이며 원본 해시는 같은 폴더의 manifest.json에 기록한다.

- 질감: 종이 섬유와 잘린 가장자리, 두께와 겹침, 부드러운 접촉 그림자를 함께 유지한다. 색상만 밝게 바꾸는 것으로 디테일 개선을 대신하지 않는다.
- 공간: 청록색 외피 안에 따뜻한 황금빛과 주황색 종이 층이 깊이를 만든다. 앞·중간·뒤가 분명하고 인물의 얼굴과 손이 잘 읽힌다.
- 인물: 요나 V2의 곱슬머리·수염·둥근 얼굴·산호색 조끼·크림색 옷·짙은 허리띠를 장면마다 유지한다. 새로운 자세에도 같은 인물로 보여야 한다.
- 자세: 무릎은 바닥에 닿고 종아리와 발은 뒤로 접힌다. 서 있는 인물을 세로로 압축해 무릎 꿇기로 표시하지 않는다.
- 구성: 책과 카메라를 고정하고 장면을 책 위에 부착한다. 빛과 여백은 주인공의 간절한 표정과 기도하는 손을 돋보이게 한다.

## 전체 애니메이션 스타일 기준 · 2026-10-17 사용자 확정

사용자는 “지금 너가 만든 스타일로 애니를 다 진행하고 싶다”고 확정했다. 새 시안 10장과 추가된 니느웨 회개 시안, 총 11장의 입체 종이 팝업북 스타일을 앞으로 제작·수정할 애니메이션의 공통 품질 기준으로 삼는다. 아래 번호는 시안 번호이며 실제 장면 ID·순서가 아니다. 스타일 채택과 실제 동작·최종 영상 승인은 구분한다.

- 겹종이 두께·섬유·잘린 가장자리·접촉 그림자를 유지한다. 평평한 색 판이나 색상 보정만으로 대체하지 않는다.
- 크림색 책·배경, 청록/코발트 바다, 따뜻한 금빛·산호색의 조화를 유지한다. 얼굴·손·행동이 분명히 읽혀야 한다.
- 요나는 둥근 얼굴·짙은 곱슬머리와 수염·크림색 옷·산호색 겉옷·짙은 허리띠를 유지한다. 다른 작품에는 그 작품의 주인공 정체성을 적용한다.
- 시안마다 다른 선박 구조·선원 의상·인물 비율은 실제 연속 장면 제작 전에 통일한다. 책·카메라와 기존 대본·음성·사건 순서는 보존한다.
- 그림을 통째로 흔들지 않고 인물·관절·소품·앞중뒤 배경을 분리하여 연기한다. 종이 접힘 상세는 ANIMATION_GUIDE의 새 스타일 접힘 품질 절을 따른다.

## 공통 제작 순서

1. 최신 소스·사용자 결정·작품 기록을 확인하고 승인 이미지와 현재 구현을 나란히 비교한다. 기존 미반영 변경을 보존한다.
2. 장면의 감정, 주인공, 실제 음성의 의미 단위, 행동 순서, 접촉 대상과 끝 자세를 짧게 설계한다. 대표 시안이 이미 승인되었다면 이를 제작 기준으로 삼는다.
3. 승인 구도를 유지하며 배경·인물·소품과 움직일 관절·손을 분리한다. 원본, 프롬프트, 자산 버전·해시, 적용 장면을 기록한다. 생성 시안을 한 장 통째로 흔드는 것으로 인물 연기를 대신하지 않는다.
4. 주요 연기를 먼저 완성한다. 팔·손·소매·머리·몸통의 회전축과 가림 순서를 맞추고 시작·중간·끝 자세를 실제 화면으로 확인한다.
5. 파도·바람·물방울 등 보조 움직임을 더한다. 여러 파도는 위상·크기·속도를 달리하고 바람은 책 바깥에서 들어오는 방향과 돛의 반응이 일치하게 한다.
6. 기존 페이지 접힘 축과 공통 진행값에 연결한다. 오른쪽 페이지와 기존 종이가 함께 접히고 다음 종이는 접힌 상태부터 함께 펼쳐져야 한다. 책 전체를 닫거나 빈 페이지 뒤에 갑자기 그림을 띄우지 않는다.
7. 실제 브라우저에서 연속 재생·음성·중간 자세·일시정지/재개·되감기·재진입을 확인한다. 전환 변경 시 정방향과 역방향의 0/25/50/75/100%를 확인한다.
8. 확인된 결함을 수정한 뒤 빌드·비공개 배포하고 사용자에게 확인 경로와 검수 범위를 전달한다. 코드 검사, 정지 시안 승인, 웹 동작 검수, 최종 MP4 승인은 각각 구분한다.

## 동작의 원인과 접촉을 표현하는 기준

| 상황 | 반드시 보이는 동작 | 불합격 예 |
|---|---|---|
| 폭풍과 짐 버리기 | 배 흔들림 → 눈에 보이는 부분 파손 → 선원이 짐을 잡고 들어 던짐 → 손에서 분리되어 낙하·물보라 | 선원은 정지한 채 짐만 떨어짐, 파손보다 짐 버리기가 먼저 나옴 |
| 선장이 깨우기 | 문 앞으로 이동 → 문을 바라봄 → 손이 문에 닿는 두드림 → 문 열림 → 요나가 나옴 | 문과 떨어져 다른 곳을 보는 선장 |
| 요나를 바다에 내려놓기 | 선원 손이 요나에 닿아 지지 → 함께 이동·내리기 → 적절한 시점에 놓음 | 서로 떨어진 인물이 공중에서 밀치는 흉내 |
| 무릎 꿇고 기도 | 무릎·옷 주름·뒤로 접힌 다리와 바닥 접촉, 손 모으기에서 팔 들기로 이어지는 연기 | 인물 키만 줄이기, 기도 순간 예전 인물로 교체 |
| 갑판·물 위 소품 | 발·상자 바닥의 접촉과 그림자, 배와 함께 흔들리는 부착 좌표 | 사람·상자가 갑판 위에 떠 있음 |

시간은 해당 언어의 실제 음성과 이야기 의미에 맞춘다. 참고 캡처의 초 숫자를 다른 길이의 음성에 그대로 복사하지 않는다. 일시정지는 인물·환경·페이지를 함께 멈추며 임의 시점 탐색에도 동일한 상태를 복원한다.

## 최종 품질 검수 및 반복 개선

이 절은 「하나님께 돌아온 요나」 1편과 이후 제작·수정하는 모든 작품에 적용하는 **제작 완료 및 MP4 제작 인계 전 필수 기준**이다. 권장 사항이 아니다. 기준 원문은 이 절에서만 관리하고 제작 절차·검수표는 이 문서를 참조한다. 기존 디자인 스타일·공통 에셋·로고·제목·만든이 표기·자막 위치 규정과 언어별 음성 및 맥북·집 PC 담당 경계를 유지한다.

### 필수 검수 항목

1. **디자인 완성도와 통일성**: 인물·배경·건물·사물의 그림체, 비율, 색감, 종이 질감, 입체감, 빛의 방향을 일관되게 유지한다. 품질이 낮거나 다른 장면과 어울리지 않는 에셋은 다시 제작한다. 저품질 에셋의 단순 확대나 효과로 결함을 가리지 않는다.
2. **공간 구성과 볼거리**: 허전하거나 시각적으로 지루한 공간은 이야기·장소에 맞는 배경·소품·보조 행동으로 보완한다. 전경·중경·후경의 깊이와 중요한 인물·사건의 가시성을 확보하며 자막과 주요 행동에 필요한 여백을 유지한다.
3. **종이 팝업북 애니메이션의 완성도**: 종이 재질과 접힘·펼침 구조를 유지하면서 실제 애니메이션처럼 자연스러운 행동과 장면 연출을 구현한다. 인물 전체의 단순 이동·흔들림만으로 완료 처리하지 않는다.
4. **인물 동작의 자연스러움과 연결성**: 걷기의 보폭·속도·발 접지·무게 이동·팔과 다리 움직임을 맞춘다. 발 미끄러짐·공중 부유·갑작스러운 방향 전환과 정지를 수정한다. 시선·표정·손짓·몸 돌리기·이동·정지·다음 행동이 부드럽게 이어지며 반복 경계에서 튀거나 순간적으로 원위치로 돌아가지 않아야 한다.
5. **대사와 애니메이션의 동기화**: 실제 음성의 발화 시점과 핵심 사건에 행동·표정·자막·장면 전개를 맞춘다. 의도된 선행 동작·후행 반응을 제외하고 대사보다 과도하게 빠르거나 늦는 행동이 없어야 한다. 수정 후 뒤쪽 장면까지 타이밍이 밀리지 않았는지 확인한다. 확정 대사·음성은 임의 변경·재생성하지 않는다.
6. **2초 이상 정지화면 방지**: 도입부터 마지막 장면까지 연속 **2.0초 이상** 정지하거나 사실상 정지로 느껴지는 구간을 찾아 반드시 의미 있는 애니메이션을 추가한다. 자막 변경·알아보기 어려운 미세 움직임·의미 없는 반짝임·카메라의 미세 이동만으로 통과시키지 않는다. 인물 반응·환경 변화·보조 사건·종이 구조 전개 등 장면에 맞는 볼거리를 제공하되 모든 요소를 계속 움직여 산만하게 만들지 않는다. 대사·장면 삭제나 재생 속도 증가로 기준을 피하지 않는다. 시작·종료 타임코드, 정지로 판단한 이유, 추가한 행동, 재검수 근거를 남긴다.
7. **자연스러운 책장 넘김**: 회전축·원근·두께·그림자·속도와 감속·구조물의 접힘과 펼침을 확인한다. 인물·소품의 갑작스러운 소멸, 페이지 관통, 흰 화면, 깜빡임, 레이어 오류, 에셋 지연을 없앤다. 앞 신의 마지막 행동부터 다음 신의 시작까지 연속 확인한다. 기존 페이지 부착·동시 접힘 원칙은 ANIMATION_GUIDE를 따른다.
8. **실제 재생 검증**: 모든 신을 실제 음성과 함께 **1배속**으로 재생한다. 정지 이미지·코드 검사만으로 동작·타이밍·책장 전환을 통과시키지 않는다. 자동 검출은 보조 수단이다. 버전·언어·저장 revision/해시가 명확한 연속 재생 자료와 타임코드별 근거를 확보한다. 실제 확인하지 못한 항목은 **미검증**으로 표시한다(단계 상태는 확인 대기).

### 필수 반복 개선 절차

**실제 재생 → 문제와 타임코드 기록 → 디자인·동작·연출 수정 → 해당 구간과 앞뒤 연결 재검수 → 남은 문제 수정 → 최신본 전체 연속 재생** 순서를 따른다.

- 수정 전 코드·에셋·실제 저장본·음성/타임라인의 버전과 해시를 체크포인트로 보존한다. seed와 웹 저장본을 구분한다.
- 한 번 수정했거나 정해진 반복 횟수를 채웠다는 이유로 완료 처리하지 않는다. 같은 방식으로 개선되지 않으면 원인을 다시 분석하고 구현 방법을 바꾼다.
- 승인된 작업 범위에서는 매번 사용자에게 계속 진행할지 묻지 않는다. 공통 파일은 기존 변경 보존·담당 확인·충돌 대조·순차 반영 절차를 지킨다.
- 각 반복의 변경 파일·이유·문제 ID·타임코드·검수 결과·연속 재생 자료·남은 문제를 작품 PRODUCTION_NOTES와 연결된 검수 기록에 저장한다. 과거 버전의 통과를 최신본에 자동 복사하지 않는다.
- Goal 기능이 지원되면 검증 가능한 완료 조건으로 목표를 활성화한다. 실제 호출·지원이 없으면 활성화했다고 보고하지 않는다.
- 권한·도구·실행 한도로 막히면 체크포인트·시도·사유·미해결/미검증 항목·다음 행동을 남기고 **미완료**로 보고한다. 통과 기준을 낮추지 않는다.

### 완료 판정과 인계

**100% 완료는 임의의 자체 평점이 아니라, 모든 신이 위 필수 항목을 충족하고 미해결 문제와 미검증 항목이 각각 0건인 상태**다. 최종 수정본 전체의 음성 포함 1배속 연속 재생 검수가 반드시 완료되어야 한다. 제작 완료 및 PC의 MP4 제작 인계 전에 이 기준을 적용한다.

- **웹 검수 완료**: 해당 웹 소스·저장본·언어의 전 신과 전환이 필수 기준을 충족하고 전체 연속 시청·청취 근거가 있다.
- **최종 MP4 검수 완료**: PC가 생성한 실제 최신 MP4의 파일 해시와 전체 음성 포함 1배속 재생·출력 검사 근거가 있다. 웹만 확인하고 MP4까지 검수했다고 표시하지 않는다.
- **사용자 최종 승인**: 사용자가 명시적으로 승인한 작품·언어·버전과 근거를 별도 기록한다. 기술·시각 검수 통과가 사용자 최종 작품 승인을 대신하지 않는다.

모든 해당 검수 기준을 충족했을 때만 **전체 검수 통과·사용자 최종 확인 대기**로 표시하며, 웹·MP4의 적용 범위를 반드시 병기한다. 미제작 MP4는 웹 검수와 별도로 미검증으로 남기며 작품 전체 100% 완료로 합산하지 않는다.
