# 02·07·08·09 · 검수와 사용자 승인

제작 완료와 MP4 제작 인계 전에는 [디자인·애니메이션 공통 기준의 「최종 품질 검수 및 반복 개선」](DESIGN_ANIMATION_PROTOCOL.md)을 필수 적용한다. 세부 기준은 해당 원문에서만 관리한다.

## 자동 검수·사용자 승인·변경 후 재검수

- ko/en별 MP4 SHA256·대본/음성/코드 버전·자동 검수 로그·오류 수정 결과를 기록한다. 실패·미실행·확인 불가는 통과가 아니다.
- 자동 검수 통과와 사용자 최종 영상 검수·최종 승인·공개 승인을 분리한다. 사용자가 확인한 언어와 실제 파일에만 승인 근거를 연결한다.
- 승인 이후 영상이 바뀌면 영향받는 언어의 07 자동 재검수·08 사용자 재검수·09 재승인을 수행한다. 공통 변경은 양언어를 대조한다.
- 실제 사용자 [유튜브 공개 게시] 클릭 없이 Public으로 전환하지 않는다. 공개 버튼이 미구현이면 절차도 미완료다.

## 증거 종류를 나눠 기록

| 구분 | 입증 범위 | 이것만으로 입증되지 않는 것 |
|---|---|---|
| 구문·단위 테스트 | 테스트가 검사한 코드 조건 | 실제 그림·전체 음성·사용자 만족 |
| 프레임 관찰 | 해당 버전·시각의 화면 | 프레임 사이 동작·전체 재생 |
| 재생 종료 이벤트 | 플레이어가 끝에 도달함 | 사람이 끝까지 보고 들었음 |
| 전체 시청 | 기록한 전체 영상의 시각 검수 | 별도 음질·배역 청취, 사용자 승인 |
| 전체 청취 | 기록한 음성의 전체 듣기 | 구도·종이 연결·사용자 승인 |
| 사용자 확인 | 명시적으로 확인한 범위 | 다른 버전·다른 배역·공개 허가 |

오류는 해당 언어 장면과 앞뒤 전환을 수정 후 재검수한다. 공통 장면·자산 변경은 두 언어의 영향 범위를 재검수한다. 같은 오류는 원인·수정·재확인 자료로 닫는다. 확인할 수 없는 항목을 임의로 통과로 바꾸지 않는다. 해결된 뒤 이유 없이 검사를 계속 늘리지 않는다.

## 자동화 연결 검수

PC에 별도로 맡긴 한국어 음성 요청·회신은 HANDOFF의 별도 계약으로 검사한다. 영어는 맥북 직접 생성·실측·연결·검수 기록을 확인하며 PC 음성 회신을 요구하지 않는다. 한국어 전체 완성 전에 확정 대본의 요청이 가능한지, 미승인 영어/배역/비용 조건은 생성 전에 차단하는지, 변경 발화만 처리하는지, 같은 요청 재전송은 중복 생성하지 않는지, 회신 중 문장·화자 변경과 타이밍만 변경된 경우를 구분하는지 확인한다. 일부 실패·응답 불명·중단/재개에서는 기존 성공 음성과 사용자 값을 보존한다. 오래된 회신·해시 불일치·다른 언어 결과는 최신본에 연결하지 않는다. 실제 음성 청취·전체 싱크 검수 전 content.completed를 발행하지 않는다.

HANDOFF 송수신 계약의 각 단계에 실제 증거를 연결한다. 정상 ko/en 각각 1건, 중복 이벤트, 잘못된 해시/언어/승인, 수신 중단·재시작, 업로드 응답 불명과 복구를 PC에서 검증한다. 무승인·손상 입력은 제작 전에 거절하고 기존 KO/EN 및 PC 미커밋 파일 해시가 보존되는지 확인한다. MAC 송신 단위 검사만으로 PC 수신·영상·업로드를 통과시키지 않는다.
