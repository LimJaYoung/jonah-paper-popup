# 웹 작업 관리 · 실행과 이전

## 기록의 적용 범위 · 2026-10-17 검수

아래 날짜별 구현·계정·음성 수·서버 상태는 해당 날짜의 조사 기록이다. 현재 운영 상태나 다른 환경에 그대로 적용하지 않는다. PC 로컬(`/control`, 127.0.0.1, 파일 저장)과 소유자 전용 Sites 웹(`/`, D1/R2)은 별도 환경이다. 웹 저장·배포가 PC에 자동 반영된다는 뜻이 아니다. 현재 여부는 해당 환경의 실제 코드·파일·접속 결과로 재확인한다. 최신 사용자 담당 지정과 PLAYBOOK을 우선한다. 이 검수는 문서 대조이며 PC 실행·계정 상태·전체 영상 품질 재검증이 아니다.

2026-10-12. Git 루트 `성경동화-서버` 안의 실제 프로젝트 `bible-paper-studio-2026-10-11`에서 명령을 실행합니다. 원본 자료와 기존 Sites 배포는 보존합니다.

## 접속과 사용

- 웹 작업 관리: http://127.0.0.1:5180/control
- 기존 제작실: http://127.0.0.1:5180/dashboard#work
- 공통 제작 지침: http://127.0.0.1:5180/DASHBOARD/guide.html

작품·장면·언어 선택 → 미리보기 확인 → 직접 문장·장면 시간 편집 → **저장하고 미리보기 반영** → 선택 장면 재생 순서로 수정합니다. 저장 뒤에도 장면 선택을 유지합니다. 장면 전체 시간(0.1~600초, 책장 전환 제외)과 문장 뒤 여유(0~10초)를 조절하고 **자동 시간**으로 직접 지정한 전체 길이를 해제합니다. 짧은 목표는 음성·읽기·필수 동작을 자르지 않고 실제 최소 길이를 표시합니다. 변경 음성 준비 → 자막·타임라인 → 검수 영상 → 실제 결과 확인은 별도 제작 단계입니다. 언어 데이터·승인은 STORY_GUIDE, 음성 연결은 AUDIO_GUIDE, 최종 출력은 VIDEO_EXPORT를 따릅니다. 한국어와 영어를 독립 저장하고 변경 전 복원본과 충돌 검사를 유지합니다. 미확보 음성을 재생 가능한 음성으로 표시하지 않습니다.

수정 요청 패널은 원문·작품·장면·언어·유형·변경 금지 항목을 보관합니다. 실행 전 수정은 새 revision으로 남기고 원문을 유지합니다. 실제 Codex 실행은 AI_EXECUTOR의 계정·비용·도구 격리 검사를 통과해야 합니다. 현재 차단 이유를 요청에 기록하고 보류하며 가짜 완료나 자동 유료 전환을 하지 않습니다. 요청 취소는 Git 이력·기존 결과물을 삭제하지 않습니다.

## 장면 위치 판서와 PNG 첨부

1. 작품·장면을 선택하고 미리보기에서 원하는 순간에 **이 화면에 위치 표시**를 누릅니다. 재생을 멈추고 현재 시각의 화면을 캡처합니다. 대본·시간 편집 중이면 먼저 저장합니다.
2. 화살표·사각형·자유선·글자 메모로 원하는 위치와 이동 방향을 표시합니다. **표시 이동**은 이미 그린 표시를 옮깁니다. 되돌리기·다시 하기도 사용할 수 있습니다.
3. **PNG 다운로드**로 저장하거나 **수정 요청에 PNG 첨부**를 누릅니다. 첨부한 뒤 요청 내용을 적고 **수정 요청 등록**을 눌러 함께 보관합니다. 파일에는 작품·언어·장면·시각을 표시합니다.
4. 외부에서 만든 PNG도 수정 요청의 파일 선택으로 올릴 수 있습니다. 기존 요청을 펼쳐 **이 요청에 PNG 추가**도 가능합니다. 접수·대기·보류 중이고 아직 실행 작업이 없는 요청에만 추가하며 원문과 수정 이력을 유지합니다.

PNG는 요청당 최대 4개, 파일당 8MB, 가로·세로 각각 4096px 및 1천만 화소 이하입니다. 첨부 대상 작품·언어·장면이 맞아야 등록됩니다. 외부 PNG에는 정확한 캡처 시각을 임의로 부여하지 않습니다. 그림 판서창을 닫아도 **이전 판서 열기**로 같은 탭의 판서를 다시 열 수 있습니다. PNG로 저장하지 않은 판서는 새로고침 전에 저장하세요. 첨부 준비 목록은 같은 탭에서 새로고침 후에도 유지되며, 최종 등록된 요청과 PNG는 서버 재시작 후에도 보존됩니다.

이 기능은 위치 수정 지시를 그림으로 전달하는 판서입니다. 실제 장면의 인물·소품·카메라 좌표를 직접 바꾸는 편집기는 구현하지 않았습니다. PNG가 있는 요청의 자동 실행은 담당자 이미지 확인을 기다리는 보류로 기록합니다. 이 대화에서 수정 요청 확인을 지시하면 원문과 PNG를 함께 확인할 수 있으며 자동 AI 이미지 해석·유료 생성·최종 출력으로 연결하지 않습니다.

첨부 원본과 메타데이터는 `.production/request-attachments/`에 보관합니다. 기존 요청 기록과 함께 PC 이전·백업에 포함하고 공개 Git에는 올리지 않습니다. 미리보기 캡처는 실제 장면을 1920×1080으로 만들고 판서 PNG에는 별도 80px 정보 줄을 덧붙입니다. 기존 원화·음성·MP4를 수정하지 않습니다.

## 실행·종료

Node.js 20 이상, npm, Google Chrome 데스크톱이 필요합니다. 실제 렌더링에는 Playwright와 FFmpeg/FFprobe가 필요하며 package-lock.json에 포함된 의존성으로 설치합니다.

```sh
cd "/이전한/폴더/bible-paper-studio"
npm ci
npm start
```

현재 Windows 실제 프로젝트 경로는 `C:\Users\USER\Documents\ChatGPT\성경동화-서버\bible-paper-studio-2026-10-11`입니다. 이미 의존성이 설치되어 있으므로 평소에는 `npm start`만 실행합니다. 서버가 `이미 실행 중`이라고 하면 중복 서버를 만들지 말고 기존 주소를 사용합니다. 주소를 열 수 없다면 해당 포트를 사용하는 프로세스가 이 제작소인지 확인합니다. 무관한 프로세스를 종료하지 않습니다.

종료: 실행한 터미널에서 **Ctrl+C**. 새 연결을 닫고 현재 제작 명령 종료를 기다립니다. 중간 강제 종료는 피합니다. 서버는 로그인 시 자동 시작되는 서비스로 설치되지 않았으며 컴퓨터 절전·종료 시 사용할 수 없습니다. 현재 Codex가 실행한 서버를 나중에 다시 사용할 때 연결되지 않으면 위 명령으로 직접 시작하세요.

포트 변경은 서버에서 `PORT` 환경변수 또는 `.env`를 사용합니다. 렌더링 자식 프로세스도 같은 포트를 받습니다. `HOST=0.0.0.0`은 지원하지 않습니다. 서버는 코드에서 항상 `127.0.0.1`에 바인딩합니다.

## 지침·백업·중복 방지

매 실행은 AGENTS.md → PLAYBOOK → IMPLEMENTATION_STATUS → INDEX → 작품 NOTES/RULES → 관련 MASTER 문서를 읽고 전체 원문·SHA-256을 `.production/jobs/<작업ID>.context.json`에 기록합니다. 결정적 제작 엔진에 필요한 파일을 준비하는 기능이며, AI가 연출 지침의 의미를 해석하거나 모든 제작 단계의 승인 조건을 자동 판정하는 기능은 아닙니다.

- `.production/jobs/`: 요청·실제 상태·실행 로그·지침 원문. 재시작 후 유지.
- `.production/versions/<작업ID>/story/`: 작업 직전 작품 백업. 기존 `history` 폴더는 수정하지 않으므로 중복 복사하지 않음.
- `.production/installation-backups/`: 이번 설치에서 교체한 코드의 이전 버전. 파일을 원자 교체해 기존 하드링크 복제본을 함께 수정하지 않음.
- `.production-lock/`: 서버와 `scripts/studio.mjs` CLI가 공유하는 단일 실행 잠금.

작업 중 다시 누르거나 다른 탭/CLI로 실행하면 409/오류로 거절합니다. API는 Idempotency-Key로 동일 요청 재전송 중복도 차단합니다. 서버 종료 뒤 자식 렌더러가 살아 있으면 잠금을 유지합니다. 둘 다 종료된 뒤 서버를 재시작하면 이전 작업을 `중단됨`으로 기록하고 자동 재실행하지 않습니다. 잠금 파일이 불완전하면 자동 제거하지 않고 시작 오류를 냅니다. 실제 서버/자식 프로세스가 모두 종료됐는지 확인한 뒤 해당 `.production-lock` 폴더만 별도 보존 위치로 옮기고 다시 시작하세요. 작업 ID와 오류 로그를 함께 보관하세요.

백업이 실패하면 작업은 실행하지 않습니다. 실패 작업의 부분 생성 파일은 자동 덮어복구하지 않습니다. 웹에서 해당 작업 이전 버전을 선택해 복원할 수 있습니다. 백업은 전체 작품 자산/출력을 포함해 공간을 사용합니다. 자동 삭제하지 않습니다. 프로젝트 외부 편집기나 `import-typecast.mjs` 같은 별도 스크립트는 이 잠금을 따르지 않으므로 제작 중 함께 쓰지 마세요. 백업은 로컬 파일 버전이며 다른 디스크 백업을 대신하지 않습니다.

## 환경 설정·비밀값

조회·문장 수정·타임라인·현재 자산 검수 출력에는 별도 API 키가 필요하지 않습니다. 점검 당시 OPENAI_API_KEY와 GOOGLE_CLIENT_ID는 미설정이었습니다. 기존 `.env.example` (이전 패키지는 `DEPLOYMENT/env.example`)을 참고해 필요한 서비스만 서버의 `.env` 또는 OS 환경변수로 설정합니다. 비밀값은 코드, URL, 요청 본문, 브라우저 입력창, Git에 넣지 않습니다.

- 기존 AI 초안 CLI: OPENAI_API_KEY, OPENAI_SCENARIO_MODEL, 확인한 SCENARIO_INPUT_USD_PER_M 및 SCENARIO_OUTPUT_USD_PER_M, 요청별 비용 승인 필요. 현재 요금 확인은 이번 범위에서 하지 않았습니다.
- 기존 일반 TTS: 키 외에도 현재 대본/요금/배역 승인 필요. Typecast로 확정된 작품을 OpenAI TTS로 바꾸지 않습니다.
- 기존 YouTube CLI: GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET 및 사용자 OAuth·채널 검증 필요. 이번에 인증·게시하지 않았습니다.
- CHROME_CHANNEL 기본값 chrome. CHROME_EXECUTABLE_PATH로 해당 컴퓨터의 Chrome 실행 파일을 지정할 수 있습니다. 필요 시 FFMPEG_PATH / FFPROBE_PATH를 해당 컴퓨터의 실행 파일 경로로 설정.

서버는 키 존재 여부만 표시합니다. 정적 파일 허용 목록 밖의 `.env`, `.secrets`, `.production` 원본 경로는 브라우저에서 제공하지 않습니다. 작업 기록 API는 비밀 환경변수를 반환하지 않습니다. 요청 원문에 사용자가 직접 비밀값을 입력하지 않도록 하세요.

## 집 컴퓨터로 이전

1. 실행 중인 작업이 끝난 것을 확인하고 서버를 종료합니다.
2. 실제 `bible-paper-studio` 폴더를 복사합니다. STORIES(assets/audio/output 포함), ENGINE, DASHBOARD, MASTER, management, scripts, tests, assets, vendor, package.json, package-lock.json, server.mjs, .production 기록·복원본을 포함합니다. 코드만 보내면 기존 작품이 재생되지 않습니다.
3. node_modules, dist, .production-lock, .env, .secrets는 일반 전달본에서 제외합니다. 비밀키/OAuth는 새 컴퓨터에서 별도 안전하게 설정합니다. .gitignore에 음성/영상이 있어 Git clone만으로는 이전되지 않습니다.
4. 제공된 `npm run transfer:pack`은 위 제외 규칙을 적용한 tar.gz와 SHA-256을 exports에 만듭니다. 요청/지침/작품 데이터가 포함된 개인용 파일이므로 공개 저장소에 올리지 않습니다. 비밀값을 일반 작품 파일에 넣었다면 먼저 별도 제거해야 합니다.
5. 집 컴퓨터에 Node 20 이상과 Chrome을 설치하고 압축을 풉니다. 해당 폴더에서 npm ci → npm test → npm start를 실행합니다. 다른 OS로 옮길 때 node_modules를 재사용하지 않습니다.
6. `/control`에서 작품/현재 음성 수를 확인하고 자막·타임라인 → 3초 검수 MP4를 실행해 새 컴퓨터의 출력 경로를 검증합니다. 이전 PC 절대경로가 들어 있는 과거 보고서는 이력이며 새 결과로 간주하지 않습니다.

Windows에서도 명령은 해당 프로젝트 폴더의 PowerShell에서 같습니다. tar를 사용할 수 없으면 폴더 복사 방식으로 이전합니다. Windows 데스크톱의 실제 실행·검수 범위는 WINDOWS_VERIFICATION.md에 기록합니다. 다른 컴퓨터로 이전한 뒤에는 해당 환경에서 다시 확인합니다.

## 휴대폰·외부 접속

화면은 휴대폰 폭에 맞게 구성되어 있으나 현재는 이 컴퓨터의 브라우저 전용입니다. 휴대폰에서 127.0.0.1은 휴대폰 자신을 의미합니다. 공개 터널, 공유기 포트 포워딩, 인터넷 공개 서버를 설정하지 않았습니다.

후속 외부 접속은 사용자 인증/접근 제한과 HTTPS를 제공하는 안전한 연결을 선택한 뒤 진행합니다. 현재 Host/Origin 허용 목록도 로컬 전용이므로 터널만 열면 작동한다고 가정하지 않습니다. 인증을 검증하는 앞단, 허용 Origin/Host, 세션/CSRF, 로그아웃·만료 처리를 함께 구현·검증해야 합니다. 인증 없이 허용 목록을 완화하거나 0.0.0.0으로 바꾸지 않습니다.

## Windows 이전 보완

최종 서버 운영체제는 Windows로 확인되었습니다. 구체적인 설치·검증·수동 시작은 WINDOWS.md (`WINDOWS.md`, PC 원본·현재 웹 사본 미포함)를 따릅니다. 패키지는 파일별 SHA256 목록을 포함하며 `node scripts/transfer-verify.mjs`로 검사합니다. `npm run doctor`는 현재 컴퓨터의 실행 환경을 점검합니다. 장면 제목·문장·장면 전체 시간·단계별 감상 여유를 웹에서 직접 편집할 수 있으며 저장 후 미리보기와 다음 타임라인 생성에 반영됩니다. 기존 MP4는 자동 재출력하지 않습니다. 그림 배치·새 장면 코드·연기 변경은 자동화되지 않아 수정 요청으로 보관됩니다.

## 수정 요청 → 검수 → GitHub → 보고

영속 자료는 `.production/requests/<UUID>.json`, 복원본은 기존 `.production/versions`, 검사 로그·브라우저 캡처는 `.production/request-verification/<UUID>`에 저장합니다. Git에서 제외되므로 PC 이전 시 함께 보존합니다. 요청은 원문·수정 이력·실행 시각·상태 이벤트·대상 파일·내용 diff·검사·승인·커밋·푸시·배포·미완료 항목을 구분합니다. 서버 재시작으로 끊긴 실행은 보류로 복구하며 자동 재실행하지 않습니다.

상태는 접수 → 실행 대기 → 수정 중 → 검수 중 → 검수 통과 → 커밋 완료 → 푸시 완료 → 기록 완료 → 보고 완료입니다. 승인 대기/수정 필요/실행 실패/검수 실패/푸시 실패/기록 실패/실행 취소/보류도 구분합니다. 보고 완료는 해당 요청의 기록 저장이며 전체 작품·배포 완료가 아닙니다.

`현재 파일 실제 검수`는 정해진 구문 검사·회귀 테스트·Playwright 브라우저 검사를 서버에서 실행합니다. 브라우저가 주장한 검사 결과를 수신해 통과 처리하는 API는 없습니다. 검사 전후 파일 해시를 비교하고 검사 실패 시 커밋을 차단합니다. 복사본 수정 결과의 원본 적용은 사용자가 확인하며, 이후 원본에서 다시 검사합니다. 자동 반영 체크가 켜진 요청은 최종 검사 통과 후 작업 브랜치로 반영합니다. 디자인·애니메이션 변경은 사용자 적용 승인도 요구합니다.

Git 대상은 `LimJaYoung/bible-paper-studio`만 허용합니다. 요청 시의 HEAD·파일 해시와 허용 파일 목록을 기록하며 웹에서 임의 셸 명령·파일 범위를 받지 않습니다. 별도 Git index에 검수된 파일만 준비하고, 등록 전부터 섞여 있던 미커밋 변경은 거절합니다. 비밀값·미디어·과거 이력은 제외합니다. REQ ID를 넣은 커밋과 `codex/REQ-...` 브랜치를 만들고 일반 push 후 ls-remote SHA를 대조합니다. 커밋 준비 기록을 남겨 부분 실패 재시도 시 이미 만든 브랜치를 덮어쓰지 않습니다. 사용자의 작업 트리·기본 브랜치·실제 index를 바꾸지 않습니다. push 실패는 별도 상태로 남기며 완료로 처리하지 않습니다.

현재 자연어 실행 범위는 기존 한국어 선택 장면의 허용된 문장·수치 변경입니다. 영어 자동 번역, 새 그림 생성, 임의 기능 코드 생성, 모든 작품 자동 연출은 연결되지 않았습니다. 해당 요청은 보존하여 담당 개발 작업으로 이어갑니다. master 병합·Sites 배포·YouTube 공개는 이 반영 절차에 포함되지 않습니다.

## 다른 PC의 GitHub 변경을 Windows 서버에 자동 반영

2026-10-12 `BiblePaperStudio-GitSync` 예약 작업을 등록했다. 현재 사용자가 Windows에 로그인한 동안 로그인 시 및 5분마다 `LimJaYoung/bible-paper-studio`의 `master`를 확인한다. 다른 PC에서는 작업 브랜치에 커밋·푸시하고 검수·승인 후 master에 병합한다. 작업 브랜치 푸시만으로는 서버에 반영되지 않는다. PC 종료·절전·로그아웃 또는 네트워크 단절 중에는 확인하지 못한다. Codex가 열려 있을 필요는 없다.

새 커밋 감지 → 임시 복사본에서 구문/회귀 검사 → 제작 중 여부와 로컬 변경 재확인 → 기존 서버의 PID·시작 시각·경로 확인 후 종료 → fast-forward 반영 → 서버 시작·HTTP 응답 확인 → 영속 기록 순서다. 기존 서버가 수동 중지 상태면 자동으로 켜지 않는다. 검수 로그와 이전 Git 커밋의 복원용 ref를 보관한다. 브라우저 시각·음성 검수는 이 자동 검사에 포함하지 않는다. 서버 확인 실패는 완료로 기록하지 않으며 이전 커밋을 자동 reset하는 기능은 없다.

미커밋 변경·브랜치 불일치·갈라진 이력·제작 잠금·로컬 파일 충돌·프로젝트 밖 변경은 대기한다. 의존성 및 업데이트/서버 제어 프로그램 자체의 변경도 수동 검수 대상으로 남긴다. 자동 stash/reset/강제 푸시·비밀값 전달·원본 자료 업로드·Sites 게시·유료 API 호출은 하지 않는다. 웹 미리보기 사이트의 저장 자료와 배포는 별도다.

설정/최근 상태: `.production/git-sync/config.json`, `status.json`. 상태 변경 이력: `history/`. 실제 검수 및 반영 근거: `runs/`. 확인은 `powershell.exe -NoProfile -File scripts/windows-git-sync.ps1 Status`, 즉시 확인은 `Run`, 자동 확인 중지는 `Disable`, 재개는 `Enable`을 사용한다. 잠금이 남으면 `owner.json`의 프로세스와 제작 작업을 확인한 뒤 보존 처리하며 확인 없이 삭제하지 않는다.

최초 실제 실행은 GitHub 인증·fetch·예약 실행 성공, 상태 `blocked_branch`다. 이 PC가 `codex/REQ-20261012-integrated-studio`이며 미커밋 수정사항이 있기 때문이다. 기존 서버 PID와 자료는 그대로다. **자동 확인은 활성화됐으나 실제 운영 서버 업데이트/재시작은 아직 수행하지 않았다.** 현재 변경을 보존·검수·커밋하고 master 통합 승인을 받은 뒤 로컬 기준을 정리해야 한다. 임시 로컬 Git 저장소의 실제 push/fetch/fast-forward·충돌 보호·검사 실패 차단·영속 보고·검수 복사본 검사 6개는 통과했다. 이 시험의 서버 시작/종료는 대역이며 운영 서버 재시작 성공의 근거가 아니다.
